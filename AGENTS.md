# AGENTS.md

Инструкции для ИИ-агентов (Claude Code и других), работающих с этим репозиторием.

## Команды

Go 1.27 (см. `go.mod`). golangci-lint подключён как `tool`-зависимость модуля, ставить его отдельно не нужно.

```sh
go tool golangci-lint run ./...                          # линт, как в CI
go tool golangci-lint fmt                                # формат: gofumpt + goimports
go test -race -count=1 ./...                             # тесты, как в CI
go test -race -count=1 -run '^TestName$' ./path/to/pkg   # один тест
```

CI (`.github/workflows/ci.yml`) сначала запускает линт, потом тесты с `-race`.

## Стиль кода

- Код должен читаться без пояснений: понятные имена, короткие функции, ранний выход вместо вложенности.
- Комментарий пиши только там, где код сам не может объяснить: почему сделано именно так, неочевидный инвариант, контракт публичного API (кто вызывает, что гарантируется, с каким `ctx`). Не пересказывай код, не повторяй имя функции в doc-комментарии, не оставляй заметок о ходе работы («добавлено», «исправлено», «TODO: подумать»).
- Doc-комментарий у экспортируемого идентификатора нужен, только если он добавляет контракт. Линтер их не требует (`revive: exported` отключён).
- Комментарии и строки в коде пишутся на английском, документация в `docs/` — на русском.
- Ошибки и паники ядра начинаются с `aish: `. Sentinel-ошибки называются `Err…`, типы ошибок — `…Error` (`errname`).
- Ошибки из чужих пакетов оборачивай (`wrapcheck`) и сравнивай через `errors.Is`/`errors.As` (`errorlint`). `//nolint` допустим только с конкретным линтером и объяснением (`nolintlint`).
- Импорты `github.com/GoldenDeals/aish-core` идут отдельной группой.
- Следуй форме существующего кода: пустая строка перед `return`, если перед ним несколько операторов, и после `defer mu.Unlock()`.

## Отчёт об изменениях

После каждого изменения кода коротко опиши в ответе, как изменились зависимости на трёх уровнях:

1. **Пакеты:** какие импорты между пакетами модуля и какие внешние зависимости (`go.mod`) появились или исчезли.
2. **Файлы:** какой файл начал или перестал использовать идентификаторы из другого файла.
3. **Конструкции языка:** какие типы, интерфейсы, функции и методы начали или перестали использовать, реализовывать или встраивать друг друга.

Если на каком-то уровне ничего не изменилось, напиши «без изменений».

## Архитектура

Репозиторий содержит ядро агент-харнесса `aish`. Целевой дизайн и план MVP описаны в `docs/ARCHITECTURE.md`. Ссылки вида «§N» в коде и здесь указывают на его разделы. Документ живой: перед правкой ядра прочитай нужный раздел. Код может отставать от документа или расходиться с ним в деталях (например, `HookOpt` в коде не generic), поэтому сигнатуры сверяй по коду. Реализация идёт по этапам из §11.

Главный критерий дизайна: у ядра нет привилегированного поведения, которое нельзя заменить модулем. Даже агентный цикл — обычный модуль.

- Ядро — это пакет `aish` в корне модуля. В нём только шина событий с транзакциями, журнал, реестр модулей, общие типы событий и хелперы. Логике агента в ядре не место.
- Модули подключаются статически, как в Caddy: blank-импорт и `RegisterModule` в `init()`. ID модуля имеет вид `<namespace>.<name>`. Все модули реализуют один интерфейс `Module` (`Init`) и по желанию `Validator`/`Starter`/`Stopper`. Ролевых интерфейсов (`Tool`, `Frontend`…) нет, и вводить их не нужно.
- Модули не вызывают друг друга, они общаются только событиями через шину. `Host` — весь API ядра для модуля. Это конкретный тип, а не интерфейс: generic-методы нельзя объявить в интерфейсе.

### События и хуки

- Событие — любой тип с методом `Kind()`. В пределах сессии одному `Kind` соответствует один Go-тип, иначе ядро паникует. Общие типы ядра идут без префикса (`tool.call`), типы модулей начинаются с ID модуля (`pty.command`). Общие типы (§5) — публичный API: их изменение ломает совместимость.
- Режим хука выбирается при подписке:
  - `Mutate` выполняется последовательно по убыванию приоритета и меняет рабочий экземпляр события через `*Mut[E]`, в том числе может удалить его (`Remove`);
  - `Handle` выполняется после всех Mutate и получает глубокую копию;
  - `Observe` выполняется после коммита, синхронно и до начала следующей транзакции, и тоже получает копию.
- Тип события может ограничить допустимые режимы неэкспортируемым методом `allowedModes()`. Так события ядра (`tx.*`, `module.error`) допускают только Observe.
- Приоритет — это число, при равенстве хуки упорядочиваются по ID `<instance>:<name>`. Полосы по соглашению: 2000 — нормализация и `Effects`, 1000 — политики, 500 — обогащение, 100 — исполнители (`DefaultPriority`), ниже 100 — после исполнителей.
- `EmitOpts` (`To`/`Except`/`Below`) ограничивает получателей. `Below(p)` доставляет только Mutate- и Handle-хукам с приоритетом ниже `p` («продолжить цепочку после меня»). Политика повторно порождает `tool.call` в `Envelope` с исходной `Meta`: одобренный через `Below(1000)`, отклонённый с `Denied: true` через `Below(100)`, чтобы исполнители его не получили.
- Копии для Handle и Observe делает `clone.go` через `reflect`. Экспортируемые поля копируются глубоко, неэкспортируемые поверхностно. Тип может задать своё копирование методом `Clone() T`.

### Транзакции

- В сессии открыта не больше одной транзакции, остальные ждут в FIFO-очереди. Хуки одной сессии никогда не выполняются параллельно (возможен только повторный вход через вложенный `Emit`), поэтому блокировки в хуках не нужны.
- `Emit` принимает только `ctx`, выданный ядром: `ctx` хука, `Start` или Observe-хука. Внутри хука используй только его `ctx`, иначе будет дедлок. Для чужого `ctx` ядро возвращает `ErrWouldDeadlock`.
- Если событие не дошло ни до одного Mutate- или Handle-хука, `Emit` возвращает `ErrUnhandled`, но событие остаётся в транзакции. Observe-хуки при этом не считаются. Ошибка хука не прерывает доставку: ядро записывает её как `module.error` и возвращает из `Emit` через `errors.Join`.
- Защита от циклов: отправитель не получает своё событие, повторная доставка хуку того же `Meta.ID` блокируется, а при превышении лимитов (глубина 16, 1000 событий) транзакция отменяется.
- Отменённая транзакция всё равно попадает в журнал, со статусом `cancelled`. Закоммиченные `Tx` неизменяемы. Каждая хранит `Trace`: кто какие события получил, изменил, удалил и породил.

### Прочее

- Модули пишут логи только через `h.Log()` (`slog`), а не в stdout/stderr: терминал принадлежит фронтенду.
- Конфиг пишется в формате Caddyfile и разбирается `github.com/coredns/caddy/caddyfile`, а не Caddy v2. Пример лежит в `docs/example.Caddyfile`. §7 ещё будет пересмотрен.
- Инварианты, которые должны покрывать тесты ядра, перечислены в §10.
